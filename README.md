# НЕИГРЫ Android

Один Android APK для двух ролей:

- **Телефон** — пульт ведущего.
- **Android TV / Google TV / Android TV-box** — игровой экран.

Приложение не копирует серверную игровую механику. Источник истины — существующий backend `https://nogames.mycarolina.ru`: состояние сезона, таймеры, результаты и финал остаются на сервере.

## Состояние v0.2.0

Версия v0.2.0 — результат логического аудита первой версии приложения. Перед первой реальной установкой устранены найденные расхождения с действующей веб-версией и серверным протоколом.

### Телефон

- вход через `/api/app/auth/login`;
- сохранение auth token в Android secure storage;
- восстановление текущей controller-сессии после перезапуска процесса;
- загрузка сезонов через `/api/app/store`;
- ввод 6-значного кода телевизора;
- выбор сезона и сопряжение;
- подключение к `/ws/app` как `controller`;
- синхронизация серверного времени через `sync_probe/sync_ack` каждые 2 секунды;
- выбор испытания и команды;
- запуск/пропуск видео-инструкции;
- старт испытания;
- `ГОТОВО` сначала сохраняется локально, затем отправляется серверу;
- отложенное `ГОТОВО` повторяется после reconnect с тем же `eventId`;
- старое pending-нажатие не блокирует следующий запуск;
- финал с отдельной кнопкой для обеих команд;
- клиентская защита от слишком раннего нажатия команды с форой;
- финал нельзя запустить до завершения отборочных обеими командами;
- ручная коррекция ошибочного timeout → success;
- завершение сезона;
- переключение итоговая таблица ↔ финальный экран;
- обычные команды блокируются offline, но `ГОТОВО` можно зафиксировать offline для последующей доставки;
- периодическая проверка, что live-сессия ещё существует;
- автоматическое переподключение WebSocket.

### Телевизор

- создание кода сопряжения без логина;
- срок pairing-кода определяется сервером, а не локальными часами ТВ;
- восстановление stage-сессии после перезапуска процесса;
- подключение к `/ws/app` как `stage`;
- `stage_ready` отправляется после начальной подготовки TV-клиента;
- синхронизация серверного времени через `sync_probe/sync_ack` каждые 2 секунды;
- настоящий Android fullscreen без браузерной панели;
- экран не засыпает;
- видео-инструкции через нативный Android media player (`video_player`);
- окончание ролика сохраняется как pending и повторно отправляется после reconnect;
- звук испытания и финала через `just_audio`;
- синхронизация звука и таймера по `runStartedAt` сервера;
- timed-финал считает оставшееся время, headstart/sudden-death — прошедшее время, как веб-версия;
- результат испытания, дуэль, итоговая таблица и финальная победа;
- периодическая проверка, что live-сессия ещё существует;
- автоматическое переподключение WebSocket.

## Логический аудит

В репозитории есть `tool/logical_audit.py`. Он проверяет критические свойства протокола и поведения приложения, включая:

- клиент/серверные тайминги 12 секунд / 60 секунд / 8 секунд;
- синхронизацию часов;
- сохранение и повтор `done`;
- 30-секундное серверное окно поздней доставки;
- финал и фору;
- восстановление после обрыва/перезапуска;
- завершение сезона и коррекцию timeout;
- возврат после протухшей live-сессии;
- повтор окончания видео после reconnect.

Последний локальный логический прогон v0.2.0: **28 PASS / 0 FAIL**.

Это не заменяет `flutter analyze`, `flutter test` и фактическую сборку APK. В текущей рабочей среде Flutter SDK отсутствует, поэтому компиляционные проверки выполняет GitHub Actions.

## Что пока намеренно не добавлено

- QR-сопряжение — пока используется короткий 6-значный код;
- отдельный фирменный launcher icon;
- Google Play / Firebase — для работы приложения они не нужны.

## Сборка без Android Studio

Локально ничего ставить не требуется.

1. Откройте репозиторий на GitHub.
2. Перейдите в **Actions**.
3. Выберите **Build NEIGRY Android APK**.
4. Нажмите **Run workflow**.
5. После зелёной сборки скачайте Artifact `NEIGRY-Android-<версия>`.
6. Внутри будет `NEIGRY-<версия>.apk` и SHA-256.

Workflow сам:

- ставит Java 17;
- загружает закреплённый Flutter 3.44.9;
- подготавливает Android SDK;
- генерирует `android/`, если папки нет в репозитории;
- добавляет Android TV / Leanback launcher;
- выставляет Android minSdk 24;
- запускает `flutter analyze`;
- запускает `flutter test`;
- собирает универсальный release APK.

## Подпись APK

Для первой технической сборки signing secrets не обязательны. Без них используется стандартная тестовая подпись сгенерированного Android-проекта, поэтому следующая чистая CI-сборка может не установиться поверх предыдущей.

Для постоянных обновлений поверх уже установленного APK нужны Repository secrets:

- `ANDROID_UPLOAD_KEYSTORE_B64`
- `ANDROID_UPLOAD_KEYSTORE_PASSWORD`
- `ANDROID_UPLOAD_KEY_ALIAS`
- `ANDROID_KEY_PASSWORD`

После этого workflow переключается на постоянную release-подпись. Сам keystore в Git не коммитится.

## Сервер

По умолчанию приложение собирается с:

```text
https://nogames.mycarolina.ru
```

Адрес задаётся в GitHub Actions через:

```text
--dart-define=API_BASE_URL=https://nogames.mycarolina.ru
```

### Используемые маршруты

```text
POST /api/app/auth/login
POST /api/app/auth/logout
GET  /api/app/store

POST /api/app/pairings
GET  /api/app/pairings/<pairingId>
POST /api/app/pairings/claim

GET  /api/app/live/<liveCode>
POST /api/app/live/<liveCode>/stop

WS   /ws/app
```

## Связь ролей

```text
Телефон (controller)
        │
        │ HTTPS + WSS
        ▼
nogames.mycarolina.ru
        │
        │ тот же live state
        ▼
Android TV (stage)
```

APK не вычисляет окончательный результат сам. Он показывает серверное состояние и отправляет события; сервер проверяет время, дедуплицирует `eventId`, сохраняет результаты и определяет переходы фаз.
